> 结果目录：`results/clinical_window_v9_macro/`

## 1. 为什么切换到宏动作

v8 五方向 Stage 1A 在 D-16 仅完成 7/16。教师轨迹状态上的动作匹配率为
97.38%，但在模型自身 rollout 状态上降到 77.50%。这证明失败主要来自数百步
低层导航的误差累积，而不是临床时间窗奖励本身。

v9 将职责拆分为：

```text
高层 RL：选择下一个合法切割前沿格，或选择 END
       ↓
底层确定性控制器：沿已切区域最短路径转移到目标旁，再切割目标
```

RL 仍决定切割顺序、血管暴露/封闭时机和提前松夹时机。它只不再学习
“沿已切区域向左还是向右走”。

## 2. 宏动作不是免费传送

环境为 `clinical-macro-window-v1`，动作数为 1201：

- `0..1199`：30×40 padded 网格中的目标格；
- `1200`：`end_clamp_early`；
- mask 只允许当前合法前沿格，以及当前时相下合法的 END。

选择目标后，环境会：

1. 在已切格上计算四邻接最短路径；
2. 逐格执行 transfer，每格仍增加模拟时间；
3. 若传送期间处于开放期且存在暴露未封闭血管，逐段累计 mL；
4. 若跨过 15 min 夹闭边界或 5 min 开放边界，精确切换时相；
5. 到达目标旁后才切割普通格或封闭血管分量。

观测为 `26x30x40`，在 v8 的 25 通道上增加每个合法目标的
`transfer_distance`。策略使用共享卷积的 per-cell logits，而不是 1201 个互不相关的
全连接输出。

## 3. 冻结的临床和 reward 设置

v9 首轮实验只更换控制层级，其余保持 v8：

- 夹闭最长 15 min，开放固定 5 min；
- 单格边长 4 mm，面积 16 mm²；
- 超过 1 格的血管分量处理耗时为 3 倍；
- 出血与暴露面积及全局概率系数相关；
- 已封闭血管、夹闭期或尚未暴露血管不出血；
- 时间/失血尺度继续使用 Train-only `scales_v5.json`；
- 进度总塑形 `+5`，血管封闭总塑形 `+2`；
- 完成 `+20`，失败 `-10`，训练临床成本上限 10；
- END 无直接奖励；
- 五方向环境的停滞惩罚保留在配置中，但合法宏目标每次必然产生新切割，
  因此两类停滞计数应始终为 0。

baseline 是“机械 S 形前沿优先级 + 机械 15/5 + 相同最短转移器”。RL 和 baseline
必须共享底层转移器，否则时间/失血对比不公平。

## 6. Stage 1A：宏目标 margin-BC

从头训练 1201 动作空间策略。Stage 1 屏蔽 END，教师为宏动作 S 形前沿优先级。
策略分支不使用 reward 回归目标，所以 `bc-v-weight=0`。

```bash
python train_clinical_window_ppo.py \
  --control-mode macro \
  --splits results/clinical_window_v5/frozen/splits_curriculum_d_v5.json \
  --scales results/clinical_window_v5/frozen/scales_v5.json \
  --output-dir results/clinical_window_v9_macro/runs/stage1a_macro_bc30_d_seed_2026080601_cuda \
  --early-end-mode disabled --end-action-initial-bias -4 \
  --bc-scenarios 256 --bc-epochs 30 --bc-batch-size 512 \
  --bc-learning-rate 1e-3 --bc-margin 2.0 --bc-v-weight 0 \
  --timesteps 16 --n-envs 1 --n-steps 16 --batch-size 16 --n-epochs 1 \
  --learning-rate 3e-4 --gamma 0.9999 --gae-lambda 0.98 \
  --ent-coef 0.005 --target-kl 0.2 \
  --seed 2026080601 --device cuda \
  --time-cost 1 --blood-cost 1 --progress-bonus 5 \
  --seal-progress-bonus 2 --completion-bonus 20 --failure-penalty 10 \
  --invalid-action-penalty 10 --clinical-cost-cap 10 \
  --stagnation-penalty-cap 0.05 \
  --stagnation-soft-start-steps 40 --stagnation-penalty-ramp-steps 24 \
  --stagnation-limit-steps 96 --two-cell-loop-penalty 0.25 \
  --two-cell-loop-soft-start-traversals 6 --two-cell-loop-limit-traversals 12
```

`pretrained_model.zip` 是 BC-only 模型；`final_model.zip` 经过了 16-step 脚本收尾，不得当作
BC-only 结果。

```bash
python clinical_window_evaluation.py \
  --control-mode macro \
  --splits results/clinical_window_v5/frozen/splits_stage_d_eval_v5.json \
  --split validation --limit 16 --algorithm ppo \
  --model results/clinical_window_v9_macro/runs/stage1a_macro_bc30_d_seed_2026080601_cuda/pretrained_model.zip \
  --scales results/clinical_window_v5/frozen/scales_v5.json \
  --early-end-mode disabled \
  --output results/clinical_window_v9_macro/evaluation/stage1a_macro_bc30_d16.json
```

Stage 1A 准入：

| 指标 | 门槛 |
| --- | ---: |
| 完成数 | 16/16；若为 15/16，只能做一次原因审计，不得直接进阶 |
| 平均覆盖率 | 1.0 |
| 合法动作率 | 1.0 |
| 停滞计数/失败 | 全部 0 |
| END 次数 | 0 |
| 失败 shaped return | 不得为正 |

由于宏动作 mask 只允许会生成新切割的目标，若仍出现 stagnation/two-cell，应视为
环境实现缺陷，不是训练调参问题。

## 7. Stage 1B：固定 15/5 下优化切割顺序

仅当 Stage 1A 通过后执行。宏动作 mask 已从结构上防止低层循环，首轮不再用
teacher margin 把 PPO 锁在 S 形上：

```bash
python train_clinical_window_ppo.py \

  --init-model results/clinical_window_v9_macro/runs/stage1a_macro_bc30_d_seed_2026080601_cuda/pretrained_model.zip \
  --output-dir results/clinical_window_v9_macro/runs/stage1b_macro_ppo_d_seed_2026080602_cuda \
  --early-end-mode disabled --timesteps 50000 \

  --learning-rate 3e-4 --gamma 0.9999 --gae-lambda 0.98 \
  --ent-coef 0.005 --target-kl 0.03 \
  --bc-scenarios 0 --bc-epochs 0 --rl-margin-coef 0 \
  --seed 2026080602 --device cuda \
  --time-cost 1 --blood-cost 1 --progress-bonus 5 \
  --seal-progress-bonus 2 --completion-bonus 20 --failure-penalty 10 \
  --invalid-action-penalty 10 --clinical-cost-cap 10 \
  --stagnation-penalty-cap 0.05 --two-cell-loop-penalty 0.25
```

审计所有 checkpoint，不默认选 final：

```bash
python audit_clinical_window_checkpoints.py \
  --run-dir results/clinical_window_v9_macro/runs/stage1b_macro_ppo_d_seed_2026080602_cuda \
  --splits results/clinical_window_v5/frozen/splits_stage_d_eval_v5.json \
```

选择顺序：完成率 → 覆盖率 → 原始耗时 → 原始失血 mL → transfer overhead。
shaped return 不用于选择最终模型。

## 8. Stage 2：在同一 1201 动作空间中解锁 END

END 从初始就是 action 1200，Stage 1 只是通过 mask 隐藏，所以解锁时不更换网络尺寸。

| 阶段 | END 设置 | 首轮预算 |
| --- | --- | ---: |
| 2A | `threshold`, 10 min | 50k |
| 2B | `threshold`, 5 min | 50k |
| 2C | `full` | 100k |

每个子阶段从上一阶段最佳 checkpoint 建立新实例，只改：

```text
--init-model
--output-dir
--early-end-mode / --early-end-minutes
--timesteps
--seed
```

首轮不同时修改 reward、数据池、学习率或网络，否则无法将改善归因于自主松夹。

## 9. 必须新增的审计项

每个评估除原有完成、时间、mL、END 和夹闭周期外，还必须报告：

- `macro_action_count`；
- `transfer_count` 及 `transfer_overhead`；
- `max_macro_duration_minutes` 的均值、P95、最大值；
- 每个宏动作是否在夹闭/开放边界之前开始、之后结束；
- 跨越时相边界的宏动作数量；
- RL 与 S 形的逐场景目标序列、耗时和失血对照。

当前聚合 JSON 已直接输出该指标的均值、P95 和最大值。“跨时相边界宏动作数”可由 replay 中的
`phase_change` 事件与同步 transfer/cut 事件计算，代理应将其写入最终报告。

## 10. GO / NO-GO

### 允许继续

- baseline 16/16 完成；
- Stage 1A 16/16 完成；
- 宏动作期间的时间和失血积分通过 replay 抽查；
- 不存在停滞或非法目标；
- Stage 1B 没有用降低完成率换取更低的部分轨迹成本。

### 立即停止

- 任一合法目标动作没有产生新切割；
- baseline 或 BC 出现 stagnation/two-cell；
- 自动转移没有计入时间或开放期失血；
- 单个宏动作持续超过 5 min，但报告没有分析不可中断决策的影响；
- 为了获得 END 而更换 action head 或丢弃 Stage 1 权重；
- 用训练截断后 reward 替代原始分钟/mL 做临床结论。
