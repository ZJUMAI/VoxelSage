# 平面模拟器三算法统一规划实施计划

## 1. 实现目标

维护平面模拟器前端，将 S 型 baseline、四权重规则规划器和机器学习策略整合为一套统一操作流程：

```text
选择算法 → 设置血管 → Lock Obstacles → 选择边界起点 → Run Planning → 展示和回放结果
```

前端只保留一个算法选择器和一个 `Run Planning` 按钮。三个现有后端接口保持独立：

- S 型：`POST /api/plan/serpentine`
- 规则规划器：`POST /api/plan`
- 机器学习：`POST /api/policy/plan`

机器学习模型由后端统一登记和加载。前端不得选择、传递或根据画布猜测 `policy_id`。

## 2. 算法模式

### 2.1 S 型 baseline

- 算法固定，不显示参数。
- 支持规则或不规则连通域。
- 画布最大为 50 行、50 列。

### 2.2 四权重规则规划器

- 仅在该模式下显示四个非负权重输入框。
- 默认权重与 `planner.py` 中的 baseline 保持一致：
  - `distance = 1.0`
  - `vessel_risk = 2.0`
  - `shape = 1.0`
  - `exposure = 0.75`
- 支持规则或不规则连通域。
- 画布最大为 50 行、50 列。

### 2.3 机器学习策略

- 不显示可调算法参数。
- 支持任意不超过 30 行、40 列的规则或不规则连通域。
- 后端必须重复校验尺寸、连通性、血管和起点合法性，不能只依赖前端。
- 当前模型采用 30×40 填充架构，但完整 30×40 范围尚未完成同等级科研验证；页面须保留研究模拟器提示，不能表述为临床能力。

## 3. 前端修改

修改 `static/index.html`：

1. 保留三种算法单选项和唯一的 `Run Planning`。
2. 删除 `Run ML Policy`、5×5、7×7 和 Stage-C 测试按钮及相应脚本。
3. 删除 `state.policyId`、`resolveMlPolicyId()`、`loadMlTestCase()` 和 `runPolicy()`。
4. `runPlanning()` 根据算法分别调用三个接口；ML 请求不包含 `policy_id`。
5. 规则规划器模式显示四权重面板，其他模式隐藏。
6. S 型和规则规划器使用 50×50 上限；ML 使用 30×40 上限。
7. 切换到 ML 时若现有画布超限，不自动裁剪；禁用运行并显示明确提示。
8. 保留四邻接 `orth` 语义，不增加其他移动方式。
9. 保留现有张力沙盒和统一结果回放功能。

## 4. 后端修改

修改 `trained_policy.py` 和 `app.py`：

1. 将可变尺寸模型登记为当前默认前端模型。
2. `/api/policy/plan` 始终使用后端默认模型，忽略或拒绝调用方试图覆盖的旧 `policy_id`。
3. 机器学习场景必须满足：
   - `1 <= rows <= 30`
   - `1 <= cols <= 40`
   - 域非空、在画布内且四邻接连通
   - 血管属于有效域且不位于域边界
   - 起点位于域边界且不与血管重叠
4. `/api/policy/status` 默认报告当前模型；后续模型升级只需更新后端登记。

## 5. 测试与验收

- 页面包含三个算法选项和唯一规划按钮。
- 页面不再包含旧 ML 测试控件、第二运行按钮或前端 `policy_id` 逻辑。
- 四个规则权重默认值正确。
- ML 接受合法规则域、不规则连通域和 30×40 边界值。
- ML 拒绝 31 行、41 列、越界单元、非连通域、边界血管和非法起点。
- 请求中的旧 `policy_id` 不得改变后端实际使用的模型。
- S 型、规则规划器和张力沙盒现有测试继续通过。
