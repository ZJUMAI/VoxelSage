## 1. 一句话目标

保留已经收敛的宏目标 BC 路径能力，让模型先知道“下一步准备切哪里”，再判断
continue/release；先把 clamp head 监督训练到稳定超过 `always-continue`，随后只对 clamp
head 做受约束的小步 PPO，最后才单独优化 target head 的总耗时。

不得把“继续训练更久”“直接解冻全部网络”或“再跑一轮 Optuna”作为 v10.2 的起点。

## 2. v10.1 证据与本轮假设

### 2.1 已确认的有效部分

- Stage 1A target-head BC loss 从约 `0.4` 降至 `0.008`，路径知识收敛；
- 宏目标 + 底层自动最短路可以 100% 完成 Stage D；
- v10.1 已修复 v10 的 Train/Validation 难度错配；
- 安全 mask 能阻止“存在暴露未封闭血管时 release”。

### 2.2 已确认的问题

1. Stage 1B 解冻了 target head 和 encoder。PPO 后 transfer overhead 从约 `0.25`
   升至 `0.31`，重建训练 reward 从约 `3.71` 降至 `3.54`，属于路径遗忘；
2. timing-oracle 有 353 个 release、671 个 continue。`always-continue` 原始 accuracy
   已为 `65.5%`，现有 oracle 训练 20 epoch 后 accuracy 约 `58%`，cross-entropy
   `0.679`，且没有按场景隔离的 Dev 评估；
3. oracle 标签是在给定 `target_action` 后比较 release/continue，但现有 clamp head 只接收
   feature map 的 mean/max pooling，**没有接收计划目标或自动转移路线**；
4. v10.1 最终模型在 Validation/Test/Stress 上 deterministic END 基本为 0，总耗时分别比
   baseline 多约 `0.166/0.377/0.149 min`；
5. 训练期 stochastic policy 每 episode 有约 2–4 次 END，deterministic evaluation 却退化为
   0 次，存在明显的探索—部署行为差距；
6. 当前夹闭决策通常不改变切割动作总耗时。只优化总时间和失血时，安全但不改变失血的提前
   松夹没有正向学习信号。

### 2.3 v10.2 的待验证核心假设

> clamp 决策必须以“已计划的下一目标及其自动转移路线”为条件；加入累计夹闭/缺血时间辅助
> 成本后，模型才有机会在失血安全约束下学会非零、可解释的提前松夹。

若反事实 upper bound 也不能获得这一收益，应停止本路线，而不是继续调神经网络。

## 3. 不可变更项

- 最长连续夹闭 15 min，开放阶段固定 5 min；
- 允许模型在合法时机提前结束夹闭；
- 暴露未封闭血管时禁止 release；
- 已切断血管视为超声刀已封闭，不再出血；
- 单格为 $4\text{ mm}\times4\text{ mm}=16\text{ mm}^2$；
- 大于 1 格的血管分量视为大血管，单位切除时间为普通组织的 3 倍；
- 出血单位为 mL，`bleeding_probability=1.0` 保留为当前保守研究设置；
- baseline 为机械 S 形目标顺序 + 机械 15/5；
- 保留宏目标与底层自动最短路，不恢复五方向导航；
- v10.2 首轮张力模拟关闭，张力权重为 0；
- v10.1 Test/Stress 已被访问，永久降级为历史诊断集，不得用于 v10.2 选择或正式结论。

## 4. v10.2 控制架构

### 4.1 第一阶段使用 clamp-only 条件环境

建立 `TargetConditionedClampEnv`，动作仅为：

```text
0 = continue clamp schedule
1 = release now
```

每个决策点按以下顺序执行：

```text
当前环境状态
  -> 冻结的 BC target policy 选择下一宏目标
  -> 底层规划器计算自动转移路线和预计动作耗时
  -> 将 planned target / route 写入 observation
  -> clamp policy 选择 continue 或 release
  -> 环境执行“相位决策 + 自动转移 + 切割/封闭”
```

clamp-only PPO 不得产生、覆盖或重新采样 target action。

### 4.2 clamp observation 至少增加

- `planned_target`：单格 one-hot 通道；
- `planned_route`：自动转移路径 mask；
- `target_is_vessel`；
- `target_is_large_vessel`；
- `target_exposed_vessel_area_mm2`；
- `route_near_exposed_vessel`；
- `planned_macro_duration_fraction`；
- 当前夹闭时长、开放时长、累计夹闭时长；
- 当前暴露未封闭血管面积与预计出血率；
- 下一次强制相位切换的剩余时间。

clamp scorer 输入必须同时包含：

1. 全局 pooled feature；
2. `planned_target` 位置处的局部 feature；
3. 路线 pooled feature；
4. 上述标量。

禁止仅使用整图 mean/max pooling 复现 v10.1。

### 4.3 后续联合阶段

只有 clamp-only 阶段通过后，才实现/启用顺序式联合策略：

```text
PLAN phase：target head 选择目标
CLAMP phase：observation 显示已选目标，clamp head 决策
EXECUTE：环境执行宏动作并返回真实 reward
```

优先使用两阶段环境状态机和 action mask，避免在独立的
`MultiDiscrete([2,1200])` 分布中继续假设 clamp 与 target 条件独立。

## 5. Reward 与评价目标

### 5.1 增加缺血代理量

定义累计夹闭时间：

$$
I=\int_0^T \mathbf{1}[\text{phase}(t)=\text{clamped}]\,dt
$$

单位为 min，对应现有 `total_clamped_minutes`。它只是研究用缺血代理，不等同于真实肝损伤。

### 5.2 训练 reward

使用增量形式：

$$
r_t=
-\frac{\Delta T_t}{T_{\mathrm{scale}}}
-\lambda_B\frac{\Delta B_t}{B_{\mathrm{scale}}}
-\lambda_I\frac{\Delta I_t}{I_{\mathrm{scale}}}
+r_{\mathrm{terminal}}
$$

首个 clamp-only Pilot 固定：

```text
time_cost       = 1.0
blood_cost      = 1.0
ischemia_cost   = 1.0
completion_bonus = 5.0
failure_penalty  = 10.0
progress/seal/transfer/mechanics shaping = 0
```

`I_scale` 必须仅在新 Train split 上，以机械 15/5 baseline 的非零累计夹闭时间中位数校准。

不得给 END 固定正奖励。END 的收益只能来自减少后续累计夹闭时间，同时仍满足失血安全约束。

### 5.3 模型选择为约束问题，不按总 reward 排名

最终优先级：

1. completion/legal/safety 硬约束；
2. 失血非劣效；
3. 总耗时最短；
4. 总耗时近似相同时，累计夹闭时间更短；
5. transfer overhead 更低。

训练 reward 只用于梯度，不能替代原始 min、mL 和配对 CI。

## 8. Gate A：反事实 upper bound

在冻结 BC target 路径上，对每个合法候选状态穷举：

```text
A = continue + 同一 planned target + 同一后续 target policy
B = release  + 同一 planned target + 同一后续 target policy
```

保存 $\Delta T$、$\Delta B$、$\Delta I$ 和综合 $\Delta C$。分别报告：

- release 可获益状态比例；
- 去除近零 advantage 后的比例；
- oracle 相对机械 15/5 的总时间、失血和累计夹闭时间；
- 安全 release 数量；
- 不同目标类别、血管面积和夹闭时长下的收益分层。

GO 条件：在 Oracle-Dev 上，精确 oracle 必须在失血安全门内显著减少累计夹闭时间，且至少存在
5% 非平局的安全 release 状态。若 oracle 本身没有收益，立即 NO-GO，禁止训练分类器。

## 9. Stage 1：target-conditioned oracle 监督学习

### 9.1 数据

- 首轮至少 8,192 个状态；不足时增加 Train 场景，不重复复制样本；
- split 必须按 `scenario_id` 分组，不能把同一 episode 的相邻状态拆到 Train/Dev；
- `|advantage| < epsilon` 的样本标为 neutral 或从二分类训练中排除；
- 保存每个样本的 planned target、route 摘要、两条反事实结果和标签来源；
- 报告类别比例以及 `always-continue`、随机和规则阈值基线。

### 9.2 学习目标

优先采用多任务模型：

- 分类：release / continue；
- 回归：$\Delta B$、$\Delta I$、$\Delta C$；
- false release 的分类损失权重为 false continue 的 3–5 倍；
- advantage 越大，样本权重越高。

不要只报告 raw accuracy。强制报告：

- balanced accuracy；
- AUROC 与 AUPRC；
- release precision/recall；
- unsafe-release false-positive rate；
- Brier score 或 calibration curve；
- 反事实 regret；
- deterministic rollout 的实际 END 次数。

### 9.3 Stage 1 GO 条件

- Oracle-Dev AUROC $\ge 0.75$；
- balanced accuracy $\ge 0.70$；
- unsafe-release false-positive rate $\le 5\%$；
- release recall $\ge 50\%$；
- rollout 相对 always-continue 减少累计夹闭时间，同时通过失血安全门；
- deterministic END 不为 0；
- clamp 决策随 planned target 改变的反事实测试通过。

未通过时只允许修改 clamp 输入、oracle 数据或监督 loss；禁止启动 PPO/Optuna。

## 10. Stage 2：clamp-only 保守 PPO

初始化为 Stage 1 最佳 oracle checkpoint，并同时冻结：

- BC target head；
- target feature extractor；
- 底层自动转移器。

首轮 Pilot：

```text
timesteps       = 20k
learning_rate   = 1e-5
n_epochs        = 2–3
clip_range      = 0.1
target_kl       = 0.01
ent_coef        = 0 或 1e-4
oracle_kl_coef  = 0.2（首轮固定）
checkpoint      = 每 2k steps
```

PPO loss 中增加对 oracle policy 的 KL/BC anchor，避免 stochastic END 探索把监督初始化冲掉。

每个 checkpoint 必须在固定 Probe-64 上同时执行：

1. deterministic rollout；
2. stochastic rollout（至少 5 次重复或固定多 seed）。

直接记录真实 `mean_episode_reward`，不得只从时间/失血均值事后重建。还要记录：

- reward 各分量；
- 时间、失血、累计夹闭时间；
- END 总数和每 episode 分布；
- unsafe END；
- transfer overhead；
- clamp logits/probability；
- 相对 oracle 的 KL 与 regret；
- target checkpoint 训练前后 hash。

### 10.1 Early stopping

出现任一情况立即恢复上一安全 checkpoint 并停止当前 seed：

- Probe deterministic reward 连续两次下降；
- 失血安全门失败；
- unsafe END 非零；
- deterministic END 退化为 0；
- target 参数 hash 变化；
- oracle regret 连续两次升高；
- completion/legal 低于 100%。

### 10.2 Stage 2 GO 条件

至少 3 个独立 seed 均满足：

- Probe 和 Oracle-Dev 完成率/合法率 100%；
- 失血非劣效；
- deterministic END 非零且 unsafe END 为 0；
- 累计夹闭时间优于机械 15/5；
- 不增加总耗时超过预设非劣效界值；
- clamp-only 期间 transfer overhead 与冻结 target baseline 数值一致或仅有浮点误差。

## 11. Stage 3：单独优化 target head 的总耗时

只有 Stage 2 GO 后才执行。

- 固定通过安全门的 clamp policy；
- 先只解冻 target head，encoder 继续冻结；
- 从 Stage 1A BC target 初始化；
- 加入对 BC/S 路径的 KL 或 imitation anchor；
- 以总时间和 transfer 为主要训练信号，失血继续作为安全约束；
- 首轮同样只做 20k Pilot，每 2k steps 固定 Probe 评估；
- 不允许同时解冻 target head 与 encoder。

Stage 3 GO：3 seed 在 Validation 上均满足安全门，平均总耗时低于机械 S baseline，且至少平均改善
而非仅在候选之间“最短”。应同时报告配对时间差 95% CI；若样本量不足以证明优效，明确标记
探索性结果。

## 12. Stage 4：可选联合微调

仅当 clamp-only 与 target-only 都独立通过后才考虑：

- clamp/target head 使用不同 learning rate；
- encoder 首轮仍冻结；
- 保留两个监督 anchor；
- 训练最多 10k–20k steps；
- 任一安全或路径指标恶化立即回滚。

只有 Stage 4 确实比 Stage 2/3 最佳模型改善，才保留联合模型。否则采用两个独立阶段的最佳安全
checkpoint，不得为了“架构完整”强行选择联合模型。

## 13. Optuna 使用条件

在 Stage 1 和单组 Stage 2 Pilot 未通过前，**禁止 Optuna**。

通过后，Optuna 只能使用 Tuning split，搜索范围限制为：

- clamp/target learning rate；
- oracle/BC KL 系数；
- entropy；
- clip range、target KL；
- `ischemia_cost`；
- 血量约束的拉格朗日系数或有限 `blood_cost` 范围。

Trial 必须以至少 2 个训练 seed 的稳健统计为目标。约束：completion/legal 100%、unsafe END 0、
失血非劣效、deterministic END 非零。Optuna Pareto 点只是候选，不是最终模型。

## 14. Validation / Test / Stress

### 14.1 Validation

- 候选超参数冻结后，每组 3 个新训练 seed；
- Validation-128 只做候选确认，不做每 2k checkpoint early stopping；
- 逐场景保存 paired time/blood/ischemia；
- 使用 scene bootstrap；跨训练 seed 同时报告均值、最差 seed 和 seed 间方差。

### 14.2 Test

架构、权重、seed 选择规则和 checkpoint 完全冻结后，只访问新 Test-128 一次。失败即 v10.2
NO-GO。失败后允许把结果用于明确标注的 postmortem，但该 Test 永久失去正式独立测试资格。

### 14.3 Stress

Stress 必须使用 Gate 0 已冻结的真实参数扰动，不得只是 Stage D 的另一个随机 seed。不得根据
Stress 结果回头选择模型。

## 15. 强制训练图表

每次阶段报告至少输出：

1. target BC train/dev loss；
2. oracle train/dev classification 与 regression loss；
3. AUROC、AUPRC、calibration；
4. fixed Probe deterministic/stochastic reward 曲线；
5. reward 分量曲线；
6. Probe 时间、失血、累计夹闭时间；
7. END 次数、unsafe END 和 release probability；
8. oracle KL/regret；
9. target 阶段 transfer overhead 和 BC KL；
10. Validation 的 paired time/blood/ischemia CI；
11. 若运行 Optuna，输出可行 trial 与 Pareto 图。

不同 `blood_cost/ischemia_cost` 的 reward 曲线不得画在同一纵轴上直接比较。训练池 rolling 曲线
必须标注为 diagnostic，固定 Probe 才能用于 early stopping。

## 16. 立即 NO-GO 条件

- 直接复用 v10.1 Test/Stress 做选择；
- 未把 planned target/route 输入 clamp head；
- oracle 数据按状态随机拆分而不是按场景拆分；
- oracle 未超过 always-continue 就启动 PPO；
- deterministic END 为 0 仍宣称学会时机；
- clamp-only 阶段 target hash 改变或 transfer 明显变化；
- 仅凭 reward 上升选择失血不安全模型；
- 只报告训练 accuracy，不报告 false release 与 held-out Dev；
- 在固定路径下声称 clamp 决策降低了总手术时间，却没有机制或配对证据；
- Stage 2 未过就解冻 target/encoder；
- Validation/Test 不保存逐场景记录；
- Stress 只是换随机 seed；
- 未生成强制图表和 Gate 报告。

```text
  -> Stage 1 GO/NO-GO
  -> Stage 2 clamp-only 20k PPO Pilot
  -> 3 seed Probe/Oracle-Dev 确认
  -> Stage 2 GO/NO-GO
  -> Stage 3 target-only 总耗时优化

  -> Validation-128 多 seed 冻结确认

  -> 输出报告与全部图表
```

代理遇到 NO-GO 必须停止后续训练，在报告中写清证据和建议；不得未经研究者确认自动放宽安全门。
