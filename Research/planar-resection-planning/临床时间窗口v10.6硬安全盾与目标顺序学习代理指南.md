# 临床时间窗口 v10.6 硬安全盾与目标顺序学习代理指南

> 版本：v10.6-shielded-target-learning-handoff-v1（2026-08-12）  
> 执行目录：`Research/planar-resection-planning`  
> 新结果目录：`results/clinical_window_v10_6_shielded_learning/`  
> 本轮性质：新正式数据上的安全目标顺序学习；**允许 BC 和最多一轮 DAgger，禁止 PPO/Optuna**  
> 适用边界：二维环境、张力与失血量均为未经临床标定的研究代理，不是临床决策系统

## 0. 当前决策与起点

v10.5 corrected teacher 已在已使用的 `planner_gate` 128 场景上通过 Gate R：

- completion/legal = 100% / 1.0，failure = 0；
- safety invariant violation = 0；
- 逐场景越界 = 0/128，$\max(\Delta B)=0.00\ \mathrm{mL}<M_B=14.82\ \mathrm{mL}$；
- $\Delta B$ 95% CI = $[-177.73,-115.20]$ mL；
- $\Delta T$ 95% CI = $[-1.78,-1.45]$ min，平均 $\Delta T=-1.61$ min；
- reference/optimized 动作 hash 128/128 一致，T/B 最大误差为 0；
- optimized p50/p95 = 34.6/115.8 s，因 p95 超过 60 s，仍是
  `correct but not deployable-latency`。

这些结果只允许进入新的学习研究，不允许复用 v10.4 模型、标签或正式 split。
本指南的目标是学习 corrected teacher 在安全候选内的耗时排序，不是让神经网络
自行承担硬安全证明。

## 2. 唯一研究问题

> 在每一步均经过 policy 外精确硬安全盾，且逐场景预期模拟失血不超过
> S 形 baseline 安全预算的前提下，学习策略能否在新冻结场景上保留 corrected teacher
> 至少 50% 的平均耗时收益？

本轮主终点仍是安全可行集内的平均总耗时。排序固定为：

1. 完成、合法、无 failure/truncation；
2. 逐场景失血越界数为 0；
3. safety invariant violation 为 0；
4. $\Delta B$ 总体非劣；
5. $\Delta T$ 优效且保留至少 50% teacher 收益；
6. 上述全通过后，才比较干预率、延迟和辅助张力指标。

reward、loss、top-k 或平均指标不得越过单场景硬安全条件。

## 3. 强制保持与明确禁止

### 3.1 必须保持

- 固定自动 15/5：最多夹闭 15 min，随后开放 5 min；`END` 始终 illegal；
- v10.5 的宏动作环境、转移计时、失血积分、血管封闭和大血管 3 倍时间；
- v10.5 `candidate_targets_v105()` 的 $K=6$、round-robin、S 候选、排序和 tie-break；
- `B_total=B_past+ΔB_action+B_tail` 的完整 episode 口径；
- terminal state、精确 state fingerprint/cache 和 no-safe invariant 合同；
- baseline 和策略共用同一环境实现；
- 单格边长 4 mm，失血量始终称为“预期模拟失血量”。

### 3.2 禁止

- 解析或使用 v10.4 的 `splits_v10_4.json`、`teacher_rankings.npz`、checkpoint；
- 将 v10.5 `planner_gate` 128 场景纳入新 Train/Tuning/Validation/Test/Stress；
- 覆盖 v10.4/v10.5 任何 JSON、NPZ、checkpoint、PNG、trace 或报告；
- PPO、Optuna、reward 权重搜索、多轮 DAgger、提前松夹或新动作空间；
- 以模型预测的 risk/safe probability 替代精确硬安全盾；
- 对 Test 失败后回到训练、改阈值、换 seed 或重测 Test；
- 为通过 Gate 改 $M_B$、删最坏场景、只报 CI 或只报平均 reward；
- 把二维模拟结果描述为已验证的临床安全性。

## 4. 新正式冻结数据

### 4.1 数量与用途

使用新 seed 从场景生成器重新生成 v10.6 纯 Stage-D 数据，不从历史结果挑选场景。
固定 master seed `2026081206`，数量为：

| split | 数量 | 唯一用途 |
| --- | ---: | --- |
| `policy_train` | 448 | teacher 标签、BC 梯度、最多一轮 DAgger |
| `policy_internal_dev` | 64 | early stop、内部 Gate；不反传 |
| `tuning` | 64 | 最多 12 个预先声明的 BC 配置比较 |
| `validation` | 128 | 最多 3 个候选 × 3 个固定 seed 确认 |
| `test` | 128 | 全部冻结后一次性主评估 |
| `stress` | 128 | 预先冻结的 OOD 审计，不反向调参 |

`policy_train` 和 `policy_internal_dev` 统称 Train-512，但两者 ID 必须分开存储。
任何归一化、缺失值策略、类别权重和 $M_B$ 都只能在 `policy_train` 上计算一次。

### 4.2 失血预算

先对 `policy_train` 运行 S 形 baseline，冻结：

$$
M_B=0.05\,\overline{B_{S,\mathrm{policy\_train}}}.
$$

任何场景 $j$ 的预算为：

$$
B_{budget,j}=B_{S,j}+M_B.
$$

`B_S,j` 是对当前场景的确定性 S 形预运行，不是学习标签。报告必须明确：
策略依赖可预计算的 scene baseline，这是当前模拟器研究的边界。

### 4.3 冻结顺序与完整性

生成前必须先写 manifest，固定生成器版本、seed、数量、Stress 分布参数、bootstrap seed
和 3 个训练 seed。冻结目录至少包含：

```text
results/clinical_window_v10_6_shielded_learning/frozen/
  experiment_manifest.json
  splits_v10_6.json
  scales_v10_6.json
  split_distribution.json
  DATA_USAGE.md
  SHA256SUMS
```

解析任何场景前先完成以下检查：

1. 全部 split ID 两两无交集；
2. 与 v10.5 `planner_gate` ID 无交集；
3. 生成配置和数量与 manifest 一致；
4. `SHA256SUMS` 在训练前全通过；
5. `DATA_USAGE.md` 记录每个 split 的首次解析时间与用途。

正式顺序为：只生成并 hash 全部 split，先只解析 `policy_train/internal_dev`；
到达对应阶段才依次解析 Tuning、Validation、Test、Stress。

## 5. observation 与候选合同

### 5.1 全局 observation 必须新增

- `B_past_ml`；
- `B_baseline_scene_ml`；
- `M_B_ml`；
- `B_budget_total_ml = B_baseline_scene_ml + M_B_ml`；
- `B_remaining_ml = B_budget_total_ml - B_past_ml`；
- `B_past / max(B_budget_total, eps)` 与 `B_remaining / max(B_budget_total, eps)`；
- 当前 clamp phase、phase elapsed、episode elapsed、已夹闭/已开放时间；
- 已切比例、即时出血率、暴露/隐藏/已封闭血管统计。

所有金额特征同时保留原始 mL 字段于 audit 记录；输入模型的归一化版本只使用
`policy_train` scales。不得对负 `B_remaining` 静默 clip 为 0，这种状态必须显式触发 invariant。

### 5.2 每候选必须新增

- `is_serpentine_fallback`；
- `candidate_source_exposed/near_hidden/nearest/fill`；
- scan rank、transfer 格数/时间、目标切割时间；
- 是否跨 15/5 边界，目标完成时的 phase；
- 真实下一步 $\Delta T_a$、$\Delta B_a$（它们是当前可观测的确定性宏动作特征）；
- 新暴露/新封闭面积、操作后未封闭面积和出血率；
- 局部 embedding 及经真实 mask 的 frontier/domain 全局 context。

S 形下一目标必须是与其他目标同等可打分的候选，不得只存在于模型不可见的
exception/fallback 分支。

## 6. teacher 标签合同

只在 `policy_train` 生成训练标签。对每个访问状态 $s$ 和每个候选 $a$ 必须保存：

$$
T_{total}(a\mid s)=T_{past}(s)+\Delta T_a+T_{tail}(s'),
$$

$$
B_{total}(a\mid s)=B_{past}(s)+\Delta B_a+B_{tail}(s').
$$

标签字段至少包含：

- `T_past`、`B_past`、`ΔT_action`、`ΔB_action`；
- `T_tail`、`B_tail`、`T_total`、`B_total`；
- `tail_completion`、`tail_failure_reason`；
- `B_budget_total`、`B_remaining_before_action`；
- `safe_exact = completion and B_total <= B_budget_total + 1e-9`；
- teacher 的完整 lexicographic ranking，candidate/source/S 标记；
- state fingerprint、candidate ID、scene ID、teacher/code/data hash。

监督主目标不得只是 top-1 class。最小要求为：

1. 对安全候选的 listwise/pairwise 耗时排序；
2. 直接回归 `B_tail` 和 `B_total`，或回归二者的保守上界；
3. 辅助 `safe_exact` 头和 completion 头；
4. 在安全候选集内优先最小 `T_total`，其次 `B_total`，使用冻结 tie-break。

loss 权重必须在解析 Validation 前冻结。风险头只用于排序辅助和诊断，不产生安全许可。

## 7. policy 外精确硬安全盾

学习模型输出对当前 $K=6$ 候选的排序。执行前，独立 safety shield 对每个候选
运行 v10.5 精确宏动作 + 确定性 S-tail，仅将以下候选纳入可执行集：

$$
\mathcal A_{safe}(s)=\{a:\ completion(a)=1,\ failure(a)=0,
B_{total}(a\mid s)\le B_{budget,j}+10^{-9}\}.
$$

执行规则固定为：

1. 从 $\mathcal A_{safe}$ 中选模型分数最高的候选；
2. 并列时使用 v10.5 deterministic tie-break；
3. 模型 top-1 不安全时，记录 `shield_intervention=true`；
4. $\mathcal A_{safe}$ 为空时，记录 invariant violation，为诊断执行 S 目标，但当前场景和 Gate 直接失败；
5. shield 不读模型的 risk logit、预测 `B_tail` 或 safe probability 来做许可决定。

主结果只计入 `shielded_policy`。`unshielded_policy` 可作诊断 rollout，但无论结果多好都不能
用于 Gate 或称为安全策略。

## 8. 建议模型与训练边界

### 8.1 最小模型

```text
网格观测 -> 共享空间编码器 -> candidate local embedding --------+
frontier/domain masked mean/max context --------------------------+
全局时间/失血/预算观测 ----------------------------------+
候选显式特征 + S/source 标记 -------------------------------+
                                                                 v
                      shared scorer + T_total/B_tail/B_total/completion heads
```

- scorer 在候选间共享参数；
- frontier/domain pooling 必须使用真实 mask，不得被 padding 稀释；
- actor 不能直接读取 teacher 真实 tail cost；它们只能作为监督标签；
- 空间编码器和宽度在进入 Tuning 前冻结；
- 第一版不强制 Transformer/LSTM，不以增大模型替代 observation 语义修复。

### 8.2 允许的训练

- 首先纯 BC/listwise ranking；
- early stop 只看 `policy_internal_dev`；
- 最多 12 个预先写入 manifest 的 BC 配置，只用 Tuning 比较；
- BC 内部 rollout 未过时，允许在 `policy_train` 上做最多一轮 DAgger；
- DAgger 只标注 policy 在 `policy_train` 实际访问的状态，从原 BC 初始化重训；
- 训练 seed 必须于观察 Validation/Test 前写入 manifest。

本轮禁止 PPO 和 Optuna。如 BC/一轮 DAgger 无法通过，结论是“当前观测/模型未学会
teacher”，不是启动 reward 优化的理由。

## 9. 执行阶段与 Gate

### 9.1 L0：冻结、hash 与合同测试

必须先完成第 4 节的数据冻结，并新增不少于以下测试：

1. observation 保留 `B_past/baseline/budget/remaining`，原始值和归一化值可反查；
2. 两个局部状态相同但 `B_past` 不同的样本不会生成相同的完整 observation；
3. S 目标始终在模型候选和 shield 候选内；
4. 每个 teacher 记录的 `B_total` 精确等于 `B_past+ΔB_action+B_tail`；
5. tail 完成、failure 和 terminal round-trip 语义与 v10.5 一致；
6. shield 必定拒绝 $B_total>B_{budget}+10^{-9}$ 的候选；
7. risk head 无论输出什么都不能绕过 shield；
8. no-safe 触发 invariant failure 而非选最快 unsafe；
9. shielded rollout 确定性，相同 checkpoint/scene 的动作 hash 一致；
10. masked pooling 不受 padding 大小影响；
11. split ID 无交集，与 v10.5 planner gate 无交集；
12. train/collector 模块没有导入 Tuning/Validation/Test/Stress；
13. v10.4/v10.5 冻结 hash 保持不变；
14. 快宏动作、teacher、shield 与真实 `step()` 的 T/B/cut/phase 一致。

L0 任一失败即停止，不得收集 teacher 或训练。v10.5 12 项与 v10.4 16 项旧测试
也必须继续通过，不修改旧期望。

### 9.2 L1：新数据上的 teacher 准入

在 `policy_internal_dev` 64 场景上配对运行 S baseline 和 corrected teacher。必须全部满足：

| 指标 | Gate T 条件 |
| --- | ---: |
| completion/legal | 64/64，1.0 |
| failure/truncation/invariant | 全部 0 |
| 逐场景 $\Delta B_i\le M_B+10^{-9}$ | 64/64 |
| `max(ΔB)` | $\le M_B+10^{-9}$ |
| $\Delta B$ 95% CI 上界 | $\le M_B$ |
| $\Delta T$ 95% CI 上界 | $<0$ |
| 平均耗时效应 | $\overline{\Delta T}\le-0.005\overline{T_S}$ |

Gate T NO-GO 则停止：不生成 teacher 训练标签，不解析 Tuning/Validation/Test/Stress。

### 9.3 L2：teacher 数据质量与 BC smoke

在 `policy_train` 收集 corrected teacher 访问状态的全候选标签。采集后必须审计：

- 候选数、safe/unsafe/completion 比例；
- `B_tail/B_total/T_total` 分布与 p95/p99/max；
- S 候选缺失数 = 0；
- no-safe state = 0，invariant = 0；
- terminal label 缺失/矛盾 = 0；
- scene/state/candidate 层级的去重、hash 和数据来源；
- 超预算候选的数量与失血超额尾部，不得为类别平衡删除危险尾部。

先用固定单 seed 做 BC smoke。离线指标至少报告 safe-set top-1/top-3/NDCG、
`B_tail/B_total` MAE 与尾部低估、unsafe false-negative rate、completion recall。
离线指标只能进入 rollout，不能单独判 GO。

### 9.4 L3：内部 shielded rollout Gate

对 `policy_internal_dev` 运行 teacher、S baseline 和 shielded policy。定义 teacher 耗时收益保留率：

$$
R_T=\frac{\overline T_S-\overline T_{policy}}
{\overline T_S-\overline T_{teacher}}.
$$

必须全部满足：

| 指标 | Gate L 条件 |
| --- | ---: |
| completion/legal | 64/64，1.0 |
| failure/truncation/invariant | 全部 0 |
| 逐场景失血越界 | 0/64 |
| `max(ΔB)` | $\le M_B+10^{-9}$ |
| $\Delta B$ 95% CI 上界 | $\le M_B$ |
| $\Delta T$ 95% CI 上界 | $<0$ |
| teacher 耗时收益保留 | $R_T\ge0.50$ |

同时强制报告但不事后改阈值：shield intervention 的 action/scene rate、S 目标选择率、
模型预测 safe 但 shield 拒绝的比例、最坏 `B_total-budget`、单场 p50/p95 和总吞吐。

BC 未过 Gate L 时只允许最多一轮 DAgger。DAgger 仍未过即 NO-GO，不进入 Tuning。

### 9.5 L4：Tuning 与 Validation

Gate L GO 后才解析 Tuning-64，最多评估 manifest 中的 12 个 BC 配置。每个配置先排除
任何越界、failure 或 $R_T<0.50$ 者，在可行集内按以下顺序取最多 3 个：

1. 平均 $\Delta T$ 更小；
2. 平均 $\Delta B$ 更小；
3. shield intervention rate 更低；
4. p95 延迟更低。

候选分别用 3 个预冻结 seed 重训，一次性在 Validation-128 上评估。每个 seed 都必须通过
Gate L 的全部条件，且每个 seed 逐场景越界 0/128；不得用 3-seed 平均掩盖某一 seed
失败。按本节的冻结顺序选唯一 checkpoint/config，写入 `final_candidate_manifest.json`。

### 9.6 L5：一次性 Test 与 Stress

冻结代码、checkpoint、scales、shield、所有阈值和报告脚本后，只运行一次 Test-128。
最终 GO 要求 Test 上：

- completion/legal = 128/128 和 1.0；
- failure/truncation/invariant = 0；
- 逐场景失血越界 = 0/128，$\max(\Delta B)\le M_B+10^{-9}$；
- $\Delta B$ 95% CI 上界 $≤M_B$；
- $\Delta T$ 95% CI 上界 $<0$；
- $R_T\ge0.50$。

Test 完成后才运行 Stress-128。Stress 使用同一硬安全条件审计 OOD，但分开给出
`in-distribution decision` 和 `stress generalization decision`；Stress 结果不得用来回训当前版本。

## 10. 延迟、行为与张力辅助审计

对 teacher、纯 policy forward、shielded policy 分开计时：

- `policy_forward_ms`；
- `shield_exact_ms`；
- `end_to_end_scene_s` p50/p95；
- fixed worker topology 下的 scenes/hour；
- tail 数、精确 cache hit/miss、shield intervention 次数；
- CPU/GPU 型号、Python/PyTorch/CUDA 版本、进程/线程数。

若安全和学习 Gate 通过但 end-to-end p95 > 60 s，结论必须保留
`research GO, not deployable-latency`，不得去掉 shield 换速度。

主策略仍对 `front_tension/organ_energy/vessel_strain` 使用冻结零 mask。在 Validation/Test/Stress
的冻结轨迹上用 `mechanics_update_interval=1` 独立 replay，报告峰值/平均张力、器官能量和
血管应变。replay 不得改变动作、T/B 或 Gate 结论。

## 13. 强制停止条件
