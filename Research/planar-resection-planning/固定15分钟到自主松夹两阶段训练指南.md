# 固定 15 分钟到自主松夹：两阶段 RL 训练与 Agent 执行指南

> 版本：v1（2026-08-04）  
> 适用目录：`Research/planar-resection-planning`  
> 执行决策：可行，但必须先完成本文第 4 节的代码改造和测试  
> 结论边界：仅是二维模拟器中的训练方案，不是临床有效性或安全性证据

## 1. 一句话执行原则

不再要求一个未训练模型同时学会“走完路线”和“何时提前松夹”：

1. **阶段 1：固定 15/5**。保留五动作网络，但始终 mask
   `end_clamp_early`，先训到 stage D 可稳定完成；
2. **阶段 2：逐步解锁**。加载同一网络，从“夹闭已达 10 min 才可松夹”
   过渡到临床语义下的“夹闭开始后即可决策”，同时用只约束方向动作的
   teacher margin 保护导航。

第二阶段未通过完成率非劣效门槛前，禁止完整 Validation、三 seed 2M、
Test 和 Stress。

## 2. 为什么这个方法可行

### 2.1 环境已经支持机械 15/5

`ClinicalWindowResectionEnv._advance_time()` 会在夹闭达到 15 min 时自动转为开放，
开放达到 5 min 后自动重新夹闭。阶段 1 只需令 `action_masks()[4] == False`，
不需要重写时间和出血积分器。

### 2.2 保留五动作网络可以无损迁移

不先训四动作网络再扩成五动作。从头到尾都保留五个 logits，只改变动作
mask，因此局部—全局特征、actor、critic 和 optimizer 状态均可继承。

### 2.3 分阶段后可以准确定位失败来源

- 阶段 1 失败：导航、血管解离或封闭仍未学会；
- 阶段 1 通过、阶段 2 完成率下降：解锁动作或 PPO 更新破坏了导航；
- 阶段 2 稳定完成但从不提前松夹：场景没有时序收益，或出血信号不足；
- 频繁松夹并大量出血：失血惩罚、状态观测或 END 初始化不当。

## 3. 需要正确理解的限制

### 3.1 阶段 1 不是最终 RL 成果

固定 15/5 只是导航课程。它可以用时间和失血 reward 学习路线，但不能证明模型
学会了自主松夹。

### 3.2 提前松夹不一定对每个场景都有优势

END 本身耗时为 0，切除在开放期仍继续，所以它的主要价值是把固定的 5 min 开放
窗口移到尚未暴露血管的安全时段。如果某场景中无论何时 END 都不能改善出血，
模型继续机械 15/5 可能正是正确策略。

### 3.3 小场景不能验证临床窗口

stage A 平均约 40 格，通常不到 15 min 就完成，几乎不会触发开放期。两阶段
决策只能以 stage D 为最终门槛，A/B 只能作为导航单元测试。

## 4. 训练前必须完成的代码改造

当前代码尚不能直接执行本方案。Agent 必须先完成 4.1–4.6，不得用临时脚本
绕过仓库入口。

### 4.1 增加可审计的提前松夹模式

在环境、训练器和评估器中统一增加：

```text
--early-end-mode disabled|threshold|full
--early-end-minutes FLOAT
```

语义：

| 模式 | END mask |
| --- | --- |
| `disabled` | 始终为 false，但环境仍自动执行 15/5 |
| `threshold` | 只有当前夹闭时长 $≥$ `early_end_minutes` 时为 true |
| `full` | 恢复当前临床语义：夹闭开始后即可结束 |

`threshold` 的阈值必须满足 $0 < t < 15$ min。训练、checkpoint 审计和评估
JSON 必须写入实际模式和阈值。默认最终评估使用 `full`，禁止依靠隐式默认值。

### 4.2 导航 margin 不得压制 END

现有 margin-BC/margin-PPO 把教师方向与所有合法动作比较。阶段 2 中 END 合法后，
这会持续强迫 `teacher_direction_logit > end_logit + margin`，与自主松夹目标直接冲突。

必须把 margin 定义改成：

$$
L_{nav}=\max\left(
0,
m+\max_{a\in A_{direction,legal},a\ne a_T}z_a-z_{a_T}
\right).
$$

即 margin 只维持四个方向动作内部的教师排序，动作 4 不作为负样本。PPO 可以
依据时间—失血 reward 自由把 END 提到方向动作之上。

### 4.3 将“收集教师 buffer”与“再次 BC 优化”解耦

阶段 2 需要教师 buffer 作导航 margin，但不应每次加载 checkpoint 后都重做几十个
epoch 的 BC。实现任一可审计方式：

- 允许 `--bc-epochs 0`，仍遍历一次 `--bc-scenarios` 以构建 reservoir，但不更新网络；或
- 新增独立的 `--teacher-buffer-scenarios` 参数。

元数据必须分开记录 `bc_optimization_epochs` 和 `teacher_buffer_count`。

### 4.4 为未训练的 END logit 设置保守先验

阶段 1 中 END 总是被 mask，对应输出行不会获得有意义梯度。新建模型时必须显式：

```text
action_net.weight[END] = 0
action_net.bias[END] = -4    # 首轮建议值，必须记入元数据
```

这只是解锁初始时的安全先验，不在阶段 2 持续锁定；PPO 可以逐渐修改 END 权重。
必须增加 `--end-action-initial-bias`，禁止将此改动隐藏在模型构造函数中。

### 4.5 修复 `--init-model` 的恢复语义

当前加载路径只重设了 margin 少数字段，CLI 传入的 learning rate、`ent_coef`、
`target_kl`、`n_epochs` 等不一定真正覆盖 checkpoint 中的值。Agent 必须二选一：

1. 显式实现并测试所有可覆盖参数的 resume；或
2. 新建第二阶段 PPO 实例，仅复制 policy/value 权重，并重建 optimizer 和 rollout buffer。

推荐方案 2，因为阶段切换时优化目标和学习率确实发生改变。输出元数据必须同时
记录“请求的超参数”和“模型实际超参数”，两者不一致时立即中止。

### 4.6 必须增加的测试

1. `disabled`：夹闭过程 END 始终为 false，15 min 仍自动转开放；
2. 开放期固定 5 min，不受三种 END 模式影响；
3. `threshold=10`：9.99 min 为 false，10 min 及以后为 true；
4. `full`：与当前环境行为一致；
5. 当 END logit 极大时，方向 margin loss 不变；
6. `bc_epochs=0` 不修改模型 hash，但教师 reservoir 非空；
7. 阶段 2 加载后 policy 权重与阶段 1 一致，实际 PPO 超参数与 CLI 一致；
8. 训练和评估的 END 模式必须进入 JSON 和 replay。

完成后运行：

```bash
python -m unittest discover -s tests -p 'test_*.py'
python -m py_compile clinical_window_environment.py clinical_window_evaluation.py \
  train_clinical_window_ppo.py audit_clinical_window_checkpoints.py
git diff --check
```

## 5. 训练前 Gate 0：确认“提前松夹有收益机会”

在 Train 中的 stage D 场景上，固定同一条机械 S 形路线，比较：

- 机械 15/5；
- 在合法时刻提前 END 的离线时序搜索。

搜索只用于证明训练集上存在可优化空间，必须标为 `train-only timing oracle`，不得
替代师兄指定的机械 S 形 baseline，也不得读取 Validation/Test/Stress 调参。

至少输出：

- 有改善机会的场景比例；
- 固定路线下可达到的平均/中位失血减少；
- END 次数和时刻分布；
- 是否存在“失血减少但总时间恶化”的权衡。

若绝大多数 Train-D 场景的 oracle 与机械 15/5 完全相同，先停止阶段 2，复核
环境时间语义和场景中的血管暴露时机，不得用加大 END 奖励人工制造“学会松夹”。

## 6. 阶段 1：固定 15/5 的导航训练

### 6.1 数据和起点

1. 先补评现有 C/D `pretrained_model.zip`，不得将标准 PPO 后的 `final_model.zip`
   当成纯 BC 结论；
2. 首个新 Pilot 使用已冻结的 `splits_curriculum_d_v5.json` 完整 256 个
   Train 场景，不再 `--train-limit 64`；
3. 若 D 仍欠拟合，再新建并冻结“D 占 50%、A/B/C 共占 50%”的 Train-only
   课程池；禁止修改四组 16 例开发集。

### 6.2 训练拆分

**1A：纯 margin-BC**

- `early-end-mode=disabled`；
- `features-extractor=local_global`；
- actor/critic 不共享特征；
- 保存并单独评估 `pretrained_model.zip`；
- 先以 256 场景、30 epoch 作小心 Pilot，不足再增加场景/轮数，不以增加
  PPO 步数代替 BC 收敛。

**1B：固定窗口 margin-PPO**

- 仅当 1A 达到导航门槛时启动；
- 从 1A 冻结 checkpoint 建立新 PPO 实例；
- `early-end-mode=disabled`；
- `bc_epochs=0`，只构建教师 buffer；
- 首轮 `rl_margin_coef=0.20`，50k 步，单 seed；
- 审计每个 checkpoint，不只评估 final。

### 6.3 阶段 1 准入门槛

在固定 stage D 16 例开发集、`early-end-mode=disabled` 下：

| 指标 | 门槛 |
| --- | ---: |
| 确定性完成率 | $≥90\%$ |
| 平均覆盖率 | $≥99\%$ |
| 非法动作率 | 0 |
| 平均回穿率 | 不高于同场景 S 形 +10 个百分点 |
| 极端循环 | 不得有完成场景消耗接近 max steps |

BC-only 和 margin-PPO 都要报告。若 PPO 完成率低于 BC-only，阶段 2 必须从 BC-only
起点开始，不得使用已退化的 PPO checkpoint。

## 7. 阶段 2：逐步解锁自主松夹

每一子阶段都从上一阶段的**最佳 checkpoint**开始，不默认使用 final。

| 子阶段 | END 规则 | 首轮预算 | 目的 |
| --- | --- | ---: | --- |
| 2A | `threshold`, 10 min | 50k | 在保守区间学会改变时序 |
| 2B | `threshold`, 5 min | 50k | 扩大可选松夹区间 |
| 2C | `full` | 100k | 恢复完整临床动作语义 |

所有子阶段初始配置：

```text
bc_optimization_epochs=0
rl_margin_coef=0.20
rl_margin_updates=1
rl_margin_batch_size=256
rl_margin_buffer_size=2048
ent_coef=0.005
features_extractor=local_global
share_features_extractor=false
```

这些是 Pilot 起点，不是预先宣布的最优超参数。不得同时改 reward、END 阈值和
margin 强度，否则无法归因。

### 7.1 每个子阶段的继续条件

1. 完成率相对阶段 1 最佳 checkpoint 下降不超过 5 个百分点；
2. 平均覆盖率 $≥99\%$；
3. 无 END 连续钻规则，开放期始终固定 5 min；
4. 方向 teacher argmax match 不可持续下降；
5. 若 Gate 0 证明存在时序优化机会，至少有一部分场景的 END 次数 $>0$；
6. 与机械 15/5 S 形及阶段 1 模型做逐场景配对时间—失血比较。

任一子阶段不通过，立即停止后续解锁，审计最早退化的 checkpoint。

## 8. reward 使用原则

> **2026-08-05 更新：**v8 已在 `clinical-window-v3` 环境实现。新实验不得继续
> 使用每血管 `seal_bonus=30`，且 21 通道旧 checkpoint 不能用于 25 通道 v8。

### 8.1 两阶段首轮保持同一主 reward

两阶段保留同一组冻结 time/blood 尺度和 v8 权重：

```text
time_cost=1
blood_cost=1
progress_bonus=5
seal_progress_bonus=2  # 对整个场景归一化
completion_bonus=20
failure_penalty=10
stagnation_penalty_cap=0.05
two_cell_loop_penalty=0.25
clinical_cost_cap=10
```

禁止给 END 增加直接正奖励。否则模型可能只是为了拿奖励而松夹，无法说明它学会
了出血风险时序。

### 8.2 停滞是双检测器，不是普通 transfer 罚分

普通无进展使用 40/96 软惩罚与终止阈值；A↔B 两格循环在同边第 6 次无进展
穿越时开始惩罚，第 12 次终止。正常返回前沿不额外罚每次 transfer。具体公式和
验收以 `临床时间窗口奖励函数v8设计与验收.md` 为准。

## 9. 评估分层与数据隔离

### 9.1 开发集

`splits_stage_a/b/c/d_eval_v5.json` 的各16例已被多次用于调参，从现在起只能称为
**development gate**，不得再称为最终 Validation。

### 9.2 完整 Validation

只有当 2C 在 stage D 16 例达到：

- 确定性完成率 $≥90\%$；
- 平均覆盖率 $≥99\%$；
- 不低于阶段 1 BC-only 的完成率；
- 至少一个主要指标在底线时序审计支持下优于机械 15/5；

才能在方法和超参数冻结后一次性运行原始 96 例 Validation。

### 9.3 Test/Stress

三 seed 和模型选择完成前继续禁止读取。

## 10. 结果必须报告的指标

每个模型、END 模式和 checkpoint 至少记录：

- completion rate 和 failure reason；
- coverage；
- direction steps、transfer count 和 transfer overhead；
- total elapsed time；
- expected blood loss；
- peak/mean expected bleeding rate；
- total clamped/unclamped minutes；
- unclamped exposed minutes；
- clamp cycles 和 early-end count；
- END 时刻（夹闭已过时长）分布；
- policy 与教师的方向 argmax match（不包括 END）；
- 逐场景相对机械 S 形和阶段 1 BC-only 的配对差值。

平均失血不得单独报告；同时报告中位数、四分位数和逐例差值，防止少数极端出血
场景掩盖主体行为。

## 11. 停止条件

出现任一情况，不得扩大训练预算：

1. 阶段 1 完整 256 场景 margin-BC 在 D-16 仍无法达到 90%；
2. 解锁 END 后完成率下降超过 5 个百分点；
3. 为保持完成率必须把 margin 调到使策略与教师实质相同，且时间/失血没有改善；
4. Train-only timing oracle 表明提前 END 对绝大多数场景没有可达改善；
5. 任何训练过程为了“得到好结果”而修改已冻结开发/验证/测试场景。

## 12. Agent 交付清单

Agent 完成一轮后必须交付：

1. 代码改动和新增测试；
2. `results/clinical_window_v7/frozen/` 中的 split/scale 哈希清单；
3. Gate 0 timing opportunity audit；
4. 阶段 1 BC-only 与最佳 fixed-window checkpoint 的 D-16 JSON；
5. 2A/2B/2C 每个 checkpoint 的开发集 JSON；
6. 机械 S 形、阶段 1 BC-only、阶段 2 RL 的逐场景配对比较；
7. 单独的失败场景清单和最早退化 checkpoint；
8. 方法是否达到完整 Validation 准入门槛的明确 `GO/NO-GO` 结论。

未达到 GO 时，最终结论必须是“尚未达到准入门槛”，不得用训练期随机完成率或
局部覆盖率替代确定性完成。
