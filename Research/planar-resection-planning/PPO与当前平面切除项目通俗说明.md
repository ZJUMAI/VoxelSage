# PPO 与当前平面切除项目：通俗说明与当前工作汇报

> 面向没有系统学习过强化学习的读者。最后更新：2026-08-12。
>
> 先说结论：我们正在一个二维平面切除模拟器中研究“切除顺序和夹闭时间如何共同影响耗时与模拟出血”。目前最可靠的研究方法是一个会前瞻评估后果的规划器（depth-1 MPC），不是神经网络；最新神经网络模型虽然完成手术很快，但会在少数场景出现极端模拟出血，因此已被判定为 **NO-GO**，不能作为安全方法。PPO 是原计划中“在安全前提下进一步优化”的后续工具，但本轮不满足进入 PPO 的条件，所以没有继续训练。

本文中的出血、张力和时间均来自二维研究模拟，尚未临床标定，不能用于真实临床决策。

## 1. 我们想解决的，到底是什么问题？

可以把模拟器想成一块由 $4\,\mathrm{mm}\times4\,\mathrm{mm}$ 方格组成的肝脏切面：

- 普通方格是待切除组织；
- 一些相连的方格代表血管横截面；
- 血管周围组织切开后，血管会从“隐藏”变为“暴露”；
- 暴露的血管若在非夹闭期没有被及时封闭，就会产生模拟失血；
- 小血管封闭占一个基础动作时间；超过一个格的血管被视为大血管，封闭时间是普通血管的 3 倍；
- 夹闭时不出血，但每次夹闭最长 15 分钟，之后环境自动进入 5 分钟开放期，再恢复夹闭。

因此，好的策略不只是“哪一格离得近就切哪一格”。它还要避免在开放期附近留下已暴露、未封闭的血管。例如，为了节约几步转移而先把血管周围解离开，恰好在 5 分钟开放期出血，可能造成很大的累计失血。

我们希望比较的是：机械 S 形扫描、人工设计的规划规则、以及学习型策略，谁能更快完成切除，同时不增加失血风险。

## 2. 不必背公式的强化学习词典

| 名词 | 通俗含义 | 在本项目中的含义 |
| --- | --- | --- |
| 环境（environment） | 会根据操作改变局面的“游戏规则” | 二维切除、血管暴露/封闭、15/5 夹闭状态机、模拟失血 |
| 状态/观测（state/observation） | 决策者此刻能看到的信息 | 已切区域、当前位置、血管状态、夹闭阶段、已耗时、预计出血率等 |
| 动作（action） | 当前做出的一个选择 | 在宏动作版本中是“选择下一块要切的前沿格”；底层转移路径由环境自动执行 |
| 策略（policy） | 从局面到动作的规则 | S 形规则、人工规划器、神经网络都是策略 |
| 回合（episode） | 从开始切到完成/失败的一整台模拟手术 | 一个具体的平面场景完整切除过程 |
| 回报（reward） | 训练时用来告诉模型“这一串选择好不好”的分数 | 通常希望少耗时、少失血、完成切除；不是临床疗效本身 |
| rollout | 让策略从头跑完一次回合 | 用某个策略完整模拟一个场景，记录耗时、失血、事件和 reward |
| action mask | “当前哪些选择合法”的清单 | 只允许选择当前前沿的可切方格，禁止切到未连接区域或隐藏血管 |
| checkpoint | 训练过程某一时刻保存的模型快照 | 可被重新加载、在固定场景上复现评估的神经网络参数 |

### 2.1 什么是 PPO？

PPO（Proximal Policy Optimization，近端策略优化）是一类强化学习算法。可以把它理解为“让模型从自己做过的整台模拟手术里总结经验，然后朝总分更高的方向小步修正”。

它和背答案式学习的差别在于：PPO 不需要老师逐步告诉它“这一刻必须选第 7 格”；它自己尝试，跑完整个回合后，根据最终的耗时、失血、失败等反馈来调整。它特别擅长处理“眼前一个动作看似不错，但会影响后面很多步”的问题。

“近端”是 PPO 的安全带：新策略不能一次离旧策略太远。因为如果模型突然把原来会走的路线全部忘掉，可能从一个还可以的策略跳到极差策略。PPO 会限制每轮更新幅度，先小步试探。

不过，PPO 并不理解医学常识；它只会优化我们提供的奖励和训练场景。如果奖励只看平均成绩，或者训练数据没有覆盖罕见危险情况，PPO 也可能学会“平均更快，但偶尔灾难性出血”的策略。PPO 不是自动的安全保障。

### 2.2 什么是行为克隆（BC）？它和 PPO 有什么区别？

行为克隆（Behavior Cloning, BC）更像学生模仿老师：先让一个强规划器在很多局面给出“下一步应该选哪个目标”，神经网络学习复制这些选择。它训练快、稳定，常用来给 PPO 一个较好的起点。

本项目 v10.4 的神经网络是 **BC 模型，不是 PPO 模型**。它学习的是 teacher 给出的“候选目标排序”。原计划是：如果 BC 已经在冻结安全评估中可靠复现 teacher，才允许把它作为初始模型，进入下一阶段的受约束 PPO。实际 Gate B 没通过，因此 PPO 没有启动。

### 2.3 什么是 teacher 和 MPC？

- **teacher（教师）**：不是人类标签，而是这里较强的规划程序。它每次面对几个候选目标，分别模拟“先选这个目标后，剩余步骤按照 S 形收尾会怎样”，再选更安全、更快的那个。
- **MPC（Model Predictive Control，模型预测控制）**：每走一步都先向前看一小段后果、选当前最好动作、到下一步再重新计算。它像一位每下一刀前都先在脑中推演后续的外科医生。
- **depth-1 MPC**：这里的“向前看”是先测试一个候选宏动作，再用确定性的 S 形尾部完成其余切除，以此估计整回合后果。它不是大规模穷举，因此仍是近似规划器。

teacher 的优点是会真实比较“这个选择是否会让后续开放期遇上暴露血管”；缺点是慢，因为每一步都要进行多个反事实模拟。

## 3. 为什么从“上下左右”改成“选择下一目标格”？

早期模型动作是上下左右移动。这样做看似自然，实则要求网络同时学会两件不同难度的事：

1. 大方向上决定接下来优先处理哪一片组织、哪根血管；
2. 小方向上在已切区域里一格一格走到那里。

结果是模型很容易把精力浪费在导航细节上，出现两个格子之间往复、局部循环或超时。人类术者通常并不需要“学习如何在已经切开的区域走一步”，而是在决定下一个手术目标。

因此我们采用了**宏动作（macro action）**：模型只选择下一个合法前沿格，环境自动通过已切区域走最短路径并按实际步数计时、计出血。这相当于“高层决定目标，底层执行转移”。它减少了无意义的导航学习，也使“切除顺序”成为真正被优化的对象。

## 4. 当前模拟器里的三种算法分别是什么？

| 页面选项 | 本质 | 主要用途 | 当前状态 |
| --- | --- | --- | --- |
| A · Serpentine Baseline | 机械 S 形优先规则 | 基线对照：不主动考虑新的出血时序 | 可用 |
| B · Rule-based Planner | 人工设定权重的动态前沿规划 | 普通非学习规划对照 | 可用 |
| C · v10.4 BC Model | 模仿 depth-1 MPC 的神经网络候选打分器 | 研究演示、失败模式复现 | 可调用，但为 NO-GO |

网页的 C 模型会在用户自定义平面上输出切除过程，并显示该**单个场景**每个宏动作的 reward。这个 reward-step 曲线是当前环境重新模拟得到的，不是历史训练曲线。v10.4 的 BC 训练没有保存逐 epoch 的训练回报；而且 BC 主要优化的是“模仿 teacher 排序”，并非 PPO 的回报最大化。

## 5. v10.4 这轮实验究竟做了什么？

这一轮刻意把“是否提前松夹”先关掉：全程采用自动固定 15/5。这样可以先回答一个更基础的问题：**仅优化切除顺序，是否就能同时减少耗时和模拟失血？**

流程如下：

```text
固定并冻结场景、评价规则
        ↓
Gate A：depth-1 MPC 是否确有相对 S 形的改进空间？
        ↓ 通过
用 MPC 生成候选顺序标签，训练 BC 神经网络
        ↓
Gate B：BC 是否既快又不增加失血风险？
        ↓ 未通过
停止：不进入 PPO、Optuna 或 DAgger
```

### 5.1 Gate 是什么，为什么要设置？

Gate 就是研究中的“闸门”。某一关不通过，就不允许继续消耗未使用的 Validation/Test/Stress 数据，更不允许靠调很多权重把失败掩盖掉。

这种流程的意义是：先证明问题确实有可优化空间，再证明简化模型至少不会破坏安全，最后才讨论用 PPO 增强。否则，PPO 可能只是把一个不可靠模型训练得更自信。

### 5.2 Gate A：通过了什么？

Gate A 比较 S 形基线、最近前沿规则和 depth-1 MPC。结果表明，MPC 同时更快、模拟失血更低，说明“切除顺序”确实有真实的优化空间，不是随机波动。

这给我们一个重要结论：临床时间窗口的价值在模拟器中能够体现；只是需要一个能看见后果的决策方法。

### 5.3 Gate B：为什么失败？

在冻结的 64 个内部开发场景中：

| 方法 | 平均耗时 | 平均模拟失血 | 单场景决策墙钟 |
| --- | ---: | ---: | ---: |
| S 形基线 | 40.72 min | 310.6 mL | 2.0 s |
| depth-1 MPC teacher | 38.59 min | 155.3 mL | 252.5 s |
| v10.4 BC 神经网络 | 37.29 min | 305.1 mL | 4.8 s |

乍看 BC 似乎不错：它完成率 100%，合法动作率 100%，平均时间甚至比 teacher 更短。但是安全评价不只看平均数。

- 多数场景中，BC 的失血确实下降；失血差值中位数为 $-165.6\,\mathrm{mL}$；
- 但 11/64 个场景超过允许失血界；
- 最坏场景比 S 形多出 $6099\,\mathrm{mL}$ 模拟失血；
- 有 4 个 S 形为零失血的场景，BC 为了节省时间直接走入血管附近，出现极端失血。

这叫做**重尾风险（heavy tail）**：大多数样本不错，但少数灾难性样本足以使策略不可接受。它也是医疗决策中不能只报均值的原因。

## 6. 为什么“BC 看起来学会了 teacher”，却仍然不安全？

这是当前最关键、也最容易被误解的问题。

BC 的训练排序规则是：先保证完成，再判断是否在安全门内；在安全候选之间主要优先耗时。可是在训练 teacher 数据中的 88% 状态，所有候选都被标为“安全”。在这种状态里，老师实际上给出的主要信号是“哪个更快”，而不是“哪个的累计失血更小”。

此外，BC 的输入能看到当前一步的预计失血、暴露面积和出血率，却看不到“选择这一步后，整条后续路径的累计尾部失血会不会爆炸”。而 teacher 会真的把每个候选分支跑到结尾，利用完整的未来后果筛选。

所以两者并不对称：

```text
teacher：每个候选都实际推演到后续结束，再按安全/耗时选择
BC：只看当前 20 维特征，用一次神经网络打分后直接选择
```

BC 在训练集上 top-1 匹配率约 89.7%、top-3 约 97.9%，说明它并非完全没学到 teacher；但它学到的主要是老师常见的“快”偏好，稀少而关键的尾部安全判断没有被可靠地学会。

这不是简单把“失血权重调大”就必然能解决的问题。若只调整一个平均 reward 权重，模型仍可能用多数好场景抵消少数灾难场景；而我们需要的是对每一个危险场景都要有明确的安全约束。

## 7. 奖励函数在这里扮演什么角色？

可以把奖励函数看成给学生的评分标准。当前环境的即时 reward 大致包含：

- 耗时带来的负分；
- 模拟失血带来的负分；
- 切除进展、完成任务带来的正向塑形；
- 如启用张力模拟，还可加入张力相关成本。

在 PPO 中，模型会尽量让整回合累计 reward 更高。但有两个重要限制：

1. **reward 是代理目标，不是临床真相。** 例如模拟失血量来自“暴露面积 × 统一出血概率 × 参考流量”等假设。它适合做研究比较，但尚不代表真实患者 mL 数。
2. **平均累计 reward 不等于安全。** 某模型可以在 60 个场景略微省时得分，在 4 个场景造成极端失血；平均分仍可能不错，但从安全上应判失败。

因此当前 Gate 用的是硬性安全门和配对置信区间，而不是只挑 reward 最大的 checkpoint。Optuna 也只能在事先定义的、满足安全门的候选中帮助找权重；它不能替代安全门。

## 8. 当前我们遇到过哪些问题？

| 问题 | 表现 | 处理/结论 |
| --- | --- | --- |
| 低层方向动作太难 | 往复、局部循环、超时 | 改为宏动作：高层选目标，环境自动转移 |
| 允许提前松夹过早 | 模型学会不稳定地使用 END，失血恶化 | 先固定 15/5，分离“路线”与“松夹时机”问题 |
| 训练分布与评估分布不一致 | 简单场景训练不能泛化到复杂 Stage D | 重建并冻结统一复杂分布；但这并未解决后续尾部安全问题 |
| 平均 reward/均值看起来改善 | 少数场景出现极端失血 | 引入逐场景诊断、配对 CI、非劣失血安全门 |
| BC 与 teacher 能力不对称 | BC 复制快的常见选择，漏掉长期风险 | Gate B NO-GO；禁止直接用 PPO “拯救”它 |
| S 形网页版本显得卡住 | 每个格子都进行了与 S 形决策无关的张力求解 | 已改成轻量 S 形执行器，保留转移和血管释放规则 |

## 9. 现在到底可以说什么、不可以说什么？

可以说：

- 在当前二维模拟假设下，考虑血管暴露、固定 15/5 窗口和切除顺序，确实存在同时减少耗时与模拟失血的空间；
- depth-1 MPC 在冻结内部开发集上优于 S 形基线；
- 当前 BC 神经网络在完成率和平均耗时上表现好，但未通过失血安全准入；
- 把低层转移交给环境、让学习方法决定高层目标，比让模型逐格导航更合理。

不可以说：

- 当前 BC 模型比 S 形“临床上更安全”；
- 6099 mL 是真实患者一定会发生的失血量；
- PPO 只要再多训练就一定能解决问题；
- 因为模型平均 reward 较高，就说明方案成功。

## 10. 当前决策与下一步建议

### 已经决定的事

1. 接受 v10.4 Gate B 的 NO-GO；不再对这一 BC 模型进行 Gate C PPO、Optuna 或 DAgger。
2. 保留 v10.4 BC checkpoint 供网页研究模拟和失败案例复现，但页面必须明确其 NO-GO 状态。
3. 保持 Validation/Test/Stress 数据冻结，不为了“再试一次”而动用它们。

### 更合理的下一步

1. **工程化 teacher**：在不改动其动作、耗时和失血结果的前提下，优化 MPC 的缓存、并行和候选评估速度。它目前安全有效，真正瓶颈是约 $252.5\,\mathrm{s}$ 的单场景决策墙钟时间。
2. **审计模拟量级**：单独检查极端失血对暴露时长、血管面积、参考流量和统一出血概率的敏感性。这是在校验模拟边界，不是回头修改 Gate B 结论。
3. **若未来重启一个新版本**：不要直接继续当前 BC/PPO。应让模型显式预测累计尾部失血或其保守上界，并在网络之外设置硬安全盾：当候选存在高风险时，交给规划器审核或禁止执行。随后使用全新的冻结数据和全新的 Gate。

## 11. 一句话 takeaway

我们不是在“让 PPO 学会像医生一样切”，而是在严格的二维研究环境中检验：一个学习型策略能否在不牺牲罕见高风险场景的前提下，学会规划器已经证明有效的手术顺序。当前答案是：**它学会了快，但还没有可靠地学会避开长期失血风险；因此应停止训练它，而不是用更多 reward 调参掩盖问题。**
