## 1. 代理任务

修正当前 Gate A 将“所有合法状态都假设 release 的平均后果”误称为“exact oracle policy upper
bound”的口径错误，实现一个完整、顺序执行、只在安全且有利时 release 的 Gate A v2 policy
rollout。

完成后只能做以下二选一决定：

- **GO**：允许进入父指南 Stage 1 target-conditioned oracle 监督学习；
- **NO-GO**：完整安全 oracle 仍未通过，停止 v10.2，等待研究者决策。

本任务不得直接训练分类器，不得运行 clamp PPO，不得运行 Optuna，不得访问

## 2. 为什么必须修正，而不是接受当前 NO-GO

当前文件：

```text
results/clinical_window_v10_2/oracle_upper_bound/gate_a_upper_bound.json
```

记录了 1,720 个沿 `always-continue` 轨迹采样的合法状态。对每个状态独立比较 release 与
continue，然后对所有“假设 release”的 $\Delta B$ 求平均。当前 `+21.9 mL` 回答的是：

> 如果每个合法候选时机都 release，平均会增加多少失血？

它没有回答：

> 如果 oracle 只在 release 不增加失血且能减少累计夹闭时间时 release，完整 episode 会怎样？

代码证据：

- `_gate_a_scenario_examples()` 在采样后始终执行 `env.step(CLAMP_CONTINUE)`；
- `gate_a_upper_bound()` 只聚合独立状态差值，没有执行 oracle action；
- `blood_safe = mean_delta_blood_ml <= 0` 把全部候选 release 的均值误当成策略级安全门。

现有结果同时显示：

- 53.8% 状态满足 `delta_blood <= 0` 且缺血改善；
- 10–15 min 区间安全改善比例为 64.1%；
- 安全子集平均 $\Delta B=-167 mL$、$\Delta I=-1.11 min$。

因此当前结果是有价值的候选状态审计，但不是 policy upper bound，不能据此结束路线。

## 5. Gate A v2 策略定义

### 5.1 两个 episode policy

对 Oracle-Dev 的每个场景执行两个完整 episode：

**Baseline：**

```text
frozen BC target + always continue + mechanical 15/5
```

**Safe greedy oracle：**

```text
frozen BC target + threshold-10 safe counterfactual release policy
```

两者必须从相同场景开始，使用同一个 BC target checkpoint、同一 target selector 和相同临床参数。

### 5.2 每个决策点的动作规则

若 release 不合法，直接 continue。

若 release 合法，从当前状态深拷贝两个分支：

```text
A = continue + 当前 planned target + 后续 always-continue BC target policy
B = release  + 当前 planned target + 后续 always-continue BC target policy
```

计算：

$$
\Delta B=B_B-B_A
$$

$$
\Delta I=I_B-I_A
$$

$$
\Delta T=T_B-T_A
$$

仅当以下条件全部成立才在真实 oracle episode 中执行 release：

```text
delta_blood <= 0
delta_ischemia < -epsilon_ischemia
continue_cost - release_cost > advantage_margin
hard release mask = legal
```

首轮固定：

```text
epsilon_ischemia = 1e-6 min
advantage_margin = 1e-6
time_cost = 1
blood_cost = 1
ischemia_cost = 1
early_end_minutes = 10
```

否则执行 continue。动作执行后必须在新的真实状态重新计算 planned target 和下一次反事实，不能
预先在 baseline 轨迹上选一组 release 再批量套用。

这里的 $\Delta B\le0$ 是 upper-bound oracle 的严格逐决策安全条件，不是部署模型可见标签；
它允许验证“是否存在安全策略”，不能在最终 RL 环境中作为隐藏真值 mask。

### 5.3 不允许的伪实现

- 仍沿 baseline 轨迹采样，最后把安全状态的独立差值求平均；
- 先从 v1 examples 选 `delta_blood<=0`，不重新执行顺序 episode；
- release 后继续使用 release 前缓存的 planned target；
- 只比较单个宏动作的即时失血，不比较完整后续 episode；
- 用综合 reward 抵消正失血后仍称为“安全 release”；
- 使用随机采样或 `sample_every>1` 跳过真实 oracle episode 的决策点。

## 11. Gate A v2 统计与判定

对 oracle 与 baseline 的逐场景差值计算：

$$
\Delta T_j=T^{oracle}_j-T^{baseline}_j
$$

$$
\Delta B_j=B^{oracle}_j-B^{baseline}_j
$$

$$
\Delta I_j=I^{oracle}_j-I^{baseline}_j
$$

每项报告 mean、median、改善/持平/恶化场景数和 scene-bootstrap 95% CI。

失血允许上限沿用 5% 非劣效界值：

$$
M_B=0.05\times\overline B_{baseline}
$$

总时间非劣效界值预先固定为 baseline 平均时间的 1%：

$$
M_T=0.01\times\overline T_{baseline}
$$

### 11.1 GO 必须同时满足

- baseline 与 oracle completion/coverage/legal 均为 100%；
- failure、unsafe END 均为 0；
- oracle deterministic END 总数大于 0；
- 至少 5% 的场景执行过安全 release；
- $CI^{95\%}_{upper}(\Delta B)\le M_B$；
- $CI^{95\%}_{upper}(\Delta T)\le M_T$；
- $mean(\Delta I)<0$；
- $CI^{95\%}_{upper}(\Delta I)<0$，证明累计夹闭时间下降而非仅点估计改善；
- BC target checkpoint hash 正确，未访问 Validation/Test/Stress。

任何一条失败均为 NO-GO 或统计不确定，不得人工改成 GO。
