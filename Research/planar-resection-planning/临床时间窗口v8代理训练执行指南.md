## 1. 任务和不可变更项

目标是先在固定 15/5 时间窗下训好导航，达到准入门槛后再逐步解锁
`end_clamp_early`。不允许跳过 Stage 1 直接训练自主松夹。

以下项目已冻结，首轮 Pilot 不得修改：

- 环境：`clinical-window-v3`；
- 动作：上、下、左、右、提前结束夹闭；
- 开放期固定 5 min，夹闭最长 15 min；
- 观测：`25x30x40`；
- 单格边长 4 mm，单格面积 16 mm²；
- 大血管为超过 1 格的血管连通分量，处理耗时为普通格的 3 倍；
- 时间和失血尺度必须使用 `scales_v5.json`，不可在 Validation/Test 重算；
- baseline 仍为机械 S 形 + 机械 15/5，路径不使用时间窗启发式。

**不得加载 v7 或其他 21 通道 checkpoint。** v8 必须从新的 25 通道
模型开始。代码会主动拒绝旧模型。

## 2. v8 奖励摘要

训练奖励为：

$$
r_t=-(Q_{t+1}-Q_t)+5\Delta p_t+2\Delta s_t-L(k_t)-H(e_t)+R_t^{\mathrm{terminal}},
$$

其中：

- $Q_t=\min(10,T_t/T_{\mathrm{scale}}+B_t/B_{\mathrm{scale}})$；
- 切完全部组织的进度塑形总计 `+5`；
- 封闭全部血管的塑形总计 `+2`，不再每根血管 `+30`；
- 完成 `+20`，失败 `-10`，非法动作 `-10`；
- 普通无进展在第 41 步开始渐进惩罚，第 96 步终止；
- A↔B 同边往复在第 6 步开始每步 `-0.25`，第 12 步终止；
- 普通 transfer 没有独立罚分，END 也没有直接奖励。

`Q_t` 的上限只影响训练 reward。评估和 replay 中的原始分钟、mL 和出血率
必须完整保留。详细公式和设计证据见
`临床时间窗口奖励函数v8设计与验收.md`。

## 4. Gate A：先固定评估 baseline

```bash
python clinical_window_evaluation.py \
  --splits results/clinical_window_v5/frozen/splits_stage_d_eval_v5.json \
  --split validation --limit 16 --algorithm serpentine \
  --scales results/clinical_window_v5/frozen/scales_v5.json \
  --early-end-mode disabled \
  --output results/clinical_window_v8/evaluation/baseline_serpentine_d16.json
```

必须检查：

- `completion_rate=1.0`；
- `mean_early_end_count=0`；
- `mean_stagnation_failure=0`；
- `mean_two_cell_loop_failure=0`；
- `mean_legal_action_rate=1.0`。

任一项不满足则停止，先调查环境或冻结数据。

## 5. Stage 1A：固定 15/5 的 margin-BC

使用完整 256 个 Train-D 场景，屏蔽 END，从头初始化 25 通道模型：

```bash
python train_clinical_window_ppo.py \
  --splits results/clinical_window_v5/frozen/splits_curriculum_d_v5.json \
  --scales results/clinical_window_v5/frozen/scales_v5.json \
  --output-dir results/clinical_window_v8/runs/stage1a_bc30_d_seed_2026080581_cuda \
  --early-end-mode disabled \
  --bc-scenarios 256 --bc-epochs 30 --bc-batch-size 512 \
  --bc-learning-rate 1e-3 --bc-margin 2.0 --bc-v-weight 0.5 \
  --timesteps 16 --n-envs 1 --n-steps 16 --batch-size 16 --n-epochs 1 \
  --learning-rate 3e-4 --gamma 0.9999 --gae-lambda 0.98 \
  --ent-coef 0.005 --target-kl 0.2 \
  --features-extractor local_global --seed 2026080581 --device cuda \
  --time-cost 1 --blood-cost 1 --progress-bonus 5 \
  --seal-progress-bonus 2 --completion-bonus 20 --failure-penalty 10 \
  --invalid-action-penalty 10 --clinical-cost-cap 10 \
  --stagnation-penalty-cap 0.05 \
  --stagnation-soft-start-steps 40 --stagnation-penalty-ramp-steps 24 \
  --stagnation-limit-steps 96 --two-cell-loop-penalty 0.25 \
  --two-cell-loop-soft-start-traversals 6 --two-cell-loop-limit-traversals 12
```

这里的 `timesteps=16` 只让训练脚本完成最小 PPO 收尾；**Stage 1A 必须评估
`pretrained_model.zip`**，因为它在 PPO 之前保存，才是纯 BC 结果。不得将该 run 的
`final_model.zip` 报告为 BC-only。

```bash
python clinical_window_evaluation.py \
  --splits results/clinical_window_v5/frozen/splits_stage_d_eval_v5.json \
  --split validation --limit 16 --algorithm ppo \
  --model results/clinical_window_v8/runs/stage1a_bc30_d_seed_2026080581_cuda/pretrained_model.zip \
  --scales results/clinical_window_v5/frozen/scales_v5.json \
  --early-end-mode disabled \
  --output results/clinical_window_v8/evaluation/stage1a_bc30_d16.json
```

### Stage 1A 准入门槛

16 个 D 开发场景必须同时满足：

| 指标 | 门槛 |
| --- | ---: |
| 完成数 | 至少 15/16（`completion_rate >= 0.9375`） |
| 平均覆盖率 | `>=0.99` |
| 合法动作率 | `mean_legal_action_rate=1.0` |
| 早退 END | 0 |
| 两格循环失败 | 0，或必须单独列出并停止进阶 |
| 其他 stagnation 失败 | 0，或必须单独列出并停止进阶 |

若不达标，**立即停止，不运行 Stage 1B/2**。此时只能结论为“v8 改善了失败
信号和循环终止，但未解决 BC 的分布外导航”。下一个方法问题应转向 DAgger、
错误恢复轨迹或分层导航，不得继续放大 reward。

对所有 checkpoint 做 D-16 审计：

```bash
python audit_clinical_window_checkpoints.py \
  --run-dir results/clinical_window_v8/runs/stage1b_margin_ppo_d_seed_2026080582_cuda \
  --splits results/clinical_window_v5/frozen/splits_stage_d_eval_v5.json \
```

不默认使用 `final_model.zip`。从 audit manifest 中按以下顺序选择：

1. 完成率；
2. 覆盖率；
3. 更低原始总耗时；
4. 更低原始模拟失血 mL；
5. 更低 transfer overhead 和停滞计数。

PPO 的完成率不得低于 BC-only 5 个百分点。如果 PPO 退化，Stage 2 必须从
BC-only checkpoint 开始，不得使用退化 checkpoint。

## 7. Stage 2：逐步解锁 END

仅当 Stage 1 最佳 checkpoint 通过 D-16 准入时执行：

| 阶段 | END 配置 | 首轮步数 |
| --- | --- | ---: |
| 2A | `--early-end-mode threshold --early-end-minutes 10` | 50k |
| 2B | `--early-end-mode threshold --early-end-minutes 5` | 50k |
| 2C | `--early-end-mode full` | 100k |

每阶段都从上一阶段的最佳 checkpoint 建立新 PPO 实例，保留 Stage 1B 的其他
参数，只改：

```text
--init-model <上一阶段最佳 checkpoint>
--output-dir <新的阶段目录>
--early-end-mode/--early-end-minutes
--timesteps
--seed
```

不得同时改 reward、margin、学习率和 END 阈值，否则无法归因。每阶段都审计所有
checkpoint，并与 Stage 1 及 S 形 baseline 做逐场景配对比较。

### Stage 2 继续条件

- 完成率相对 Stage 1 最佳值下降不超过 5 个百分点；
- 平均覆盖率 `>=0.99`；
- 开放期必须仍固定 5 min；
- 不得出现 END 连续钻规则；
- Gate 0 已证明 31% Train-D 场景有时序优化空间，因此需报告哪些场景实际
  使用了 END，以及与固定 15/5 相比的原始失血变化；
- 不能用 shaped return 宣称临床改善。

## 8. 必须保存和汇报的产物

每个 run 必须保留：

```text
run_metadata.json
behavior_cloning.json
training_health_latest.json
training_health/
checkpoints/
pretrained_model.zip（若启用 BC）
final_model.zip
training_complete.json
```

每次评估报告至少包含：

- 完成数/总数、平均覆盖率和失败原因分类；
- 原始总耗时、模拟失血 mL、峰值出血率；
- transfer count/overhead；
- `max_no_progress_streak` 和 `max_same_edge_streak`；
- `stagnation_failure` 和 `two_cell_loop_failure`；
- 夹闭周期数、END 次数、开放期暴露时间；
- S 形、BC-only、最佳 PPO 的逐场景对照表；
- 明确的 GO/NO-GO 结论。

报告必须区分：

1. 奖励信号是否变得合理；
2. 循环是否更快被检测；
3. 实际完成率是否提高；
4. 在保持完成的前提下，时间或失血是否改善。

“循环在 12/96 步被终止”不等于“模型已学会探索”；只有冻结开发集完成率
提高才能支持后一结论。

## 9. 强制停止条件

出现任一情况立即停止当前路线，不进入正式 Validation/Test/Stress：

1. Stage 1A 在 D-16 少于 15/16 完成；
2. S 形 baseline 被任一停滞检测器误杀；
3. 失败轨迹 shaped return 仍为正；
4. 模型通过重复 END 逃避时间或出血成本；
5. PPO 训练越久，完成率越低，且所有 checkpoint 都低于 BC-only；
6. 为达标必须同时改动 reward、END 规则和数据分布，导致无法归因。

停止后仍需写完整失败报告，不得只报“调参未成功”。
