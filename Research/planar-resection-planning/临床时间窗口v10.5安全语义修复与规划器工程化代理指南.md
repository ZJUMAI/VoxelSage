## 3. v10.5 安全语义合同

### 3.1 完整 episode 成本

对场景 $j$，先运行 S 形 baseline，冻结：

$$
B_{budget,j}=B_{S,j}+M_B,
$$

其中 $M_B=0.05\times\overline{B_S}$，只在允许的开发数据上计算一次。

对当前状态 $s$ 和候选动作 $a$：

$$
T_{total}(a\mid s)=T_{past}(s)+\Delta T_a+T_{tail}(s'),
$$

$$
B_{total}(a\mid s)=B_{past}(s)+\Delta B_a+B_{tail}(s').
$$

安全候选必须同时满足：

- tail 完成整个 episode；
- 无 failure/truncation；
- $B_{total}(a\mid s)\le B_{budget,j}+10^{-9}$。

在安全候选中按 `(T_total, B_total, deterministic_tie_break)` 选择。过去成本对同状态的候选排序
虽是常数，但必须显式记录，以防安全预算再次被错误使用。

### 3.2 无安全候选不是普通分支

S 形下一目标必须始终在候选集合中。由确定性 S-tail 的归纳关系，若前一步安全判断正确，下一状态
应至少存在 S-tail 安全候选。若出现 `safe_candidate_count == 0`：

1. 记录 `safety_invariant_violation=true`、状态摘要和全部候选成本；
2. 为保证 rollout 可诊断，可以执行 S 形目标；
3. 当前场景和整个 Gate R 直接判失败；
4. 不得退化为“选择最快 unsafe 候选”。

### 3.3 terminal state

state payload/fingerprint 必须包含所有影响未来演化或终止判断的字段，至少包括：

- `terminated`、`truncated`、`failure_reason`；
- `cut/current/previous_direction_position`；
- `hidden/exposed/sealed`；
- clamp phase、phase elapsed、episode elapsed；
- cumulative blood、clamped/unclamped time；
- step/transfer/direction counters；
- max-step/max-time 相关状态。

候选动作若已完成 episode，tail 必须直接返回 `(0, 0, completion=True)`，不能重新进入无 frontier
循环。

### 3.4 精确 cache

v10.4 对相位和总时间按 0.1 min 取整的 key 不适合作为硬安全 reference。v10.5 reference 使用不碰撞
的确定性表示，例如 `float.hex()` 或经测试证明一一对应的整数时间单位。必须新增测试：两个相位时间
相差小于 0.1 min、但跨 15/5 边界后的失血不同，不能命中同一 cache key。

## 4. 候选集合合同

新建 `candidate_targets_v105()`，不能直接修改 v10.4 函数。候选数默认 $K=6$，确定性流程为：

1. 计算并首先加入唯一的 S 形下一目标，保证 fallback 可表示；
2. 对每个 exposed component 只保留一个可封闭入口，按 `(-area, transfer, scan_rank)` 排序；
3. near-hidden 列表按 `(-adjacent_hidden_area, transfer, scan_rank)` 排序；
4. nearest 列表按 `(transfer, scan_rank)` 排序；
5. 在 exposed、near-hidden、nearest 三个列表间 round-robin 添加未重复目标，直到 $K$；
6. 若仍不足 $K$，用全 frontier 的 `(transfer, scan_rank)` 回填；
7. 所有返回目标必须位于当前 frontier，且不得重复。

每一步记录 `candidate_source`。测试必须构造一个 S 目标较远、near-hidden 目标不在最近前 6 的场景，
确认二者仍按合同进入集合。

| 条件 | 阈值 |
| --- | --- |

## 9. 阶段 R3：行为等价性能优化

仅在 Gate R GO 后执行。先冻结 corrected reference 的动作轨迹和结果 hash，再优化实现。允许：

- persistent leaf worker pool；
- 同一状态候选 tail 批处理；
- 精确 state fingerprint 与无损 cache；
- 避免重复构造 immutable geometry；
- 合理的 scene-level/leaf-level 并行，但禁止嵌套过度订阅；
- PyTorch 不参与 teacher planner 时避免无关线程占用。

禁止：

- 改候选数、排序、tie-break、预算或 fallback；
- 用近似 tail、截短 horizon 或降低候选数换速度；
- 因浮点容差改变安全判定；
- 只比较总体均值而不比较动作序列。

### 9.1 固定 benchmark 拓扑

至少报告两种模式：

1. `latency`：`scene_workers=1`，记录单场 p50/p95；
2. `throughput`：固定 scene workers 和每 scene leaf workers，记录总 scenes/hour。

报告 CPU 型号、逻辑核数、进程数、Python 版本和起止时间。Gate A 的 51 s 与 Gate B 的 252 s
不得直接混用。

### 9.2 等价与速度门

- 128/128 action sequence hash 完全一致；
- 每场 T/B/phase/cycles/transfer 完全一致，浮点绝对误差 $\le10^{-9}$；
- safety Gate 仍全部通过；
- 相对 corrected serial reference 的单场 p50 speedup $\ge3\times$，或 p50 $\le20$ s；
- p95 $\le60$ s。

若安全与动作等价通过但速度门未过，结论写为“correct but not deployable-latency”，不得修改算法
换取一次看似通过的 benchmark。
